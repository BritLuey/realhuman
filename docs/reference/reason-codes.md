# Reason codes

> [!NOTE]
> Defined as `REASONS` and `REASON_CODES` in `@realhuman/schema` and produced by `@realhuman/engine`. The tables
> below are generated from the code by `scripts/gen-reason-codes.mjs`, and a test fails if any code is missing.

Every decision record has a `reasons` array listing all the evidence, and a `primaryReason` naming the one that
best explains its label. Reason codes go to **your backend only** and are never sent to the browser.

- **Title** is a short name for dashboards.
- **Lean** shows which way a code points: towards **bot**, towards **human**, or **neutral** (context only).
- **Weight** is how much it counts towards the bot or human evidence level. How weights become levels and labels:
  [Understanding results](../guides/understanding-results.md).

```ts
import { REASONS } from '@realhuman/schema';

REASONS.honeypot_filled.title; // 'Honeypot filled'
REASONS.honeypot_filled.lean; // 'bot'
```

## How to read them

- A record can have **several** codes. They are listed roughly in order of influence, and `primaryReason` picks the one that matters most.
- **Bot-leaning codes don't automatically mean "bot".** Only strong or conclusive bot evidence makes the label
  `bot`; a single weak signal, such as `timezone_mismatch` from a VPN user, doesn't change the label at all.
- New codes may be added in minor releases. Treat unknown codes as neutral.
